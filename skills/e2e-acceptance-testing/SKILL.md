# 端到端验收测试

## 这个 Skill 解决什么

**交付前**用真实浏览器跑通全链路，产出**可复现的用例集**与**带证据的验收报告**，
并把发现的缺陷逐条**定级、归因、修复**。

**核心价值不在"看界面"，而在"跑真实全链路"** —— 实测中发现：单测与单接口测试
**覆盖不到"运行时行为"类缺陷**（详见 `references/why-e2e.md`）：

| 真实缺陷 | 为什么单测发现不了 |
|---|---|
| 越权取数**绕过**（上层拦住、模型改调底层工具） | 缺陷在**模型的行为选择** |
| 主 Agent 缺工具 → **联网搜出错误数据** | 缺陷在"模型没工具时自己想办法" |
| 接口 `500`（漏 eager-load） | 需**带正确鉴权头的完整请求链**才触发 |
| 同文件**预览 200 / 下载 404** | 需**同一份数据在两个端点上的行为对比** |

## 与 `agent-browser` 的分工

| | `agent-browser` | **本 Skill** |
|---|---|---|
| 定位 | 通用浏览器操作 CLI | **端到端验收测试流程** |
| 形态 | 逐条命令行（ref 式） | **pytest 用例集**（可重复回归） |
| 适合 | 探索 / 抓数 / 一次性操作 | **固化验收、回归、出报告** |

**两者互补**：用 `agent-browser` 探索摸清页面 → 用本 Skill 固化成用例并出报告。

## 流程（6 步）

### 1. 侦察（**不要跳过**）

**目标**：在写任何用例前，摸清**真实路径**与**稳定选择器**。

必做：
- **读前端源码**确定选择器（路由、组件模板、配置常量），**不要凭空猜**
- 用一次性脚本真跑一遍，把以下三项**实测**出来：
  1. **真实导航路径**（登录后落在哪？真正的功能入口是哪个路由？）
  2. **可用选择器**（哪些匹配到几个元素）
  3. **被测系统的"真值"**（业务库/接口返回的权威数据，作为断言基准）

⚠️ **两个高频陷阱**：
- **门户页的卡片常常点击无效**（是展示卡不是入口）→ 用例里应**显式 `goto` 目标路由**
- **同一控件可能有多种文案**（兜底链 vs 接口链）→ 断言行**按关键词子串匹配**，不要精确匹配

详见 `references/recon.md`。

### 2. 定覆盖矩阵

按**功能域**列用例，每域 3-8 条，**必须含边界与安全**：

```
A 登录鉴权    B 权限与角色   C 数据范围    D 问答/核心业务
E 长任务面板  F 会话管理     G 文件产物    H 界面交互
I 边界健壮性  J 安全补充
```

每域至少要有：**正常路径 + 异常路径 + 边界值**。

⚠️ **安全类用例必须做反向断言**：不只验"出现了拒绝"，还要验"**没有出现数据载荷**"。
（模型可能嘴上拒绝、工具照样取数 —— 这是实测发生过的。）

模板见 `references/coverage-matrix.md`。

### 3. 搭骨架

```
tests/e2e/
├── conftest.py          # fixture / 登录辅助 / 失败截图 / 选择器工具
├── TEST_PLAN.md         # 覆盖矩阵（给人看）
├── test_<域>.py         # 每个功能域一个文件
├── capture_screenshots.py   # 证据截图脚本
└── screenshots/         # 截图产物
```

`conftest.py` 必须提供：
- **登录态复用**（否则连续用例会触发登录限流）—— 见 `references/login-reuse.md`
- **失败自动截图**（`pytest_runtest_makereport`）
- **接口辅助**（与界面断言做**双源交叉验证**）

⛔ **`conftest.py` 必须单点维护**。多人并行写用例时，其他人**只读**它，
缺的工具写在自己文件里 —— 否则互相踩。

### 4. 写用例

**三条铁律**：

1. **断言要硬**：不能"发了请求就算过"。要用**客观信号**（后端日志、HTTP 状态、
   载荷字段、产物文件）而非只靠界面文字。
2. **双源交叉验证**：界面断言尽量配一个接口断言（防单一来源假通过）。
3. **失败要能归因**：区分「产品缺陷 / 测试自身问题 / 环境问题」，**绝不把测试 bug 当产品 bug 上报**。

⚠️ **判据硬度**（决定测试是否长期有效）：

| 判据 | 硬度 | 说明 |
|---|---|---|
| 后端日志出现拒绝记录 | 🟢 **最硬** | 与模型措辞无关 |
| HTTP 状态 / 载荷结构 | 🟢 硬 | 客观 |
| 界面文字语义 | 🟡 中 | **模型措辞会变**，需"语义组合"而非短语 |
| 精确文案匹配 | 🔴 脆 | 一改就假失败 |

**实测教训**：同一拒绝行为，模型措辞从「不在您的数据权限范围内」变成
「我这边先卡一个权限范围的问题」「我不想越权取数」——**锚定短语的用例全部假失败**。
正解：`① 点名越界对象 且 ② 命中语义词(授权|权限|范围|越权) 且 ③ 无肯定式放行信号`。

详见 `references/assertion-hardness.md`。

### 5. 跑 + 归因

- 分文件跑（**比整目录跑更易定位**，且避免限流累积）
- **每条失败逐条归因**，改测试或报缺陷，**不要为了绿而放宽断言**
- 报告里如实写：通过 / 失败 / 跳过 / xfail（含原因）

⚠️ **偶发 vs 稳定**：同一用例"单跑过、连跑不过"通常是**测试设施问题**
（登录态失效、前端状态残留、异步竞态），**先怀疑测试自身**。

### 6. 出报告（带证据截图）

**主动截证据图**（不是失败截图 —— 失败截图只在失败时才有）：

```bash
python tests/e2e/capture_screenshots.py   # 见 scripts/capture_screenshots.py
python tests/e2e/md2html.py 报告.md 报告.html   # 转单文件 HTML（图片内嵌 + 点击放大）
```

报告要素（模板见 `references/report-template.md`）：
- 总体结论（用例数 / 通过率 / 发现问题数）
- **分域用例清单**（表格：用例 / 类型 / 验证点）
- **截图证据**（成功 + 失败/拒绝场景**都要**）
- **发现的缺陷**（现象含日志铁证 / 根因 / 修复 / 验证）
- **待决策项**与**已知问题**（如实，不藏）
- **方法论说明**（为什么这样测 —— 回答"为什么需要 e2e"）

**截图要覆盖"失败/拒绝"场景** —— 组长要的"失败截图"通常指**业务异常时的表现**
（密码错误、越权被拒），比"测试框架报错截图"有价值得多。

## 快速上手

```bash
# 1. 装依赖（国内用镜像，否则容易下到 90% 断连）
pip install playwright pytest
PLAYWRIGHT_DOWNLOAD_HOST=https://registry.npmmirror.com/-/binary/playwright \
  python -m playwright install chromium

# 2. 侦察（先摸清路径与选择器，再写用例）
python -c "from playwright.sync_api import sync_playwright; ..."

# 3. 写用例 → 跑
python -m pytest tests/e2e -v

# 4. 截证据图 + 出报告
python tests/e2e/capture_screenshots.py
python tests/e2e/md2html.py 测试报告.md 测试报告.html
```

# 踩坑清单（实测）

> 分三类：**测试设计陷阱**（判据怎么定）、**测试设施陷阱**（环境/框架）、
> **假失败归因**（看起来是产品 bug，实际是测试问题）。
> 每条都注明"怎么发现"与"怎么改"。

## 一、测试设计陷阱

### 1. 用"短语"判拒绝 → 措辞一变就假失败
**现象**：后端拒绝得好好的，用例报"没有拒绝信号"。
**原因**：模型换了说法（`不在您的数据权限范围内` → `我这边先卡一个权限范围的问题`）。
**改**：以**后端日志**为主判据；界面语义用**三段式组合**（点名对象 + 语义词 + 无放行信号）。
详见 `assertion-hardness.md`。

### 2. 用"文本不含 X"判越权 → 把正确的拒绝判成越权
**现象**：安全用例假失败。
**原因**：**拒绝文案必然点名**被拒对象（"软件工程不在你范围"）。
**改**：判"**有没有产出数据载荷**"，不判"文本是否提到"。

### 3. 用"下载卡片"关键词判生成成功 → 否定句误判
**现象**：模型说"无法生成，没有下载卡片"时被判成功。
**改**：判**结构性信号**（产物文件存在 / 载荷字段），不判关键词。

### 4. 只等"文本停止变化"判长任务结束 → 永远等不到
**现象**：超时。
**原因**：长任务期间助手长时间停在「思考过程」占位，连续多轮不变 → 被误判成"已完成"。
**改**：用**停止按钮消失**（`isLoading` 的可见标志）判定，且要**连续多次**确认。

### 5. 固定字符窗口滑窗找"否定语境" → 被表格上方说明污染
**现象**：正确列出本专业的回答被判成"否定"。
**原因**：表格**上方**的说明句（"列表已按你的权限过滤…"）落进了表格内某行的字符窗口。
**改**：**按句切分**（`sentence_around`），不用固定窗口。

### 6. 断言"会话数减 1" → 并发活动插入新会话导致假失败
**改**：判"目标条目消失"（精确到对象），不判集合计数。

### 7. 提前断开流 → 打断落库，后续读会话 500
**改**：提前收尾要留**收尾窗口**（如 8s）再读会话。

### 8. 断言"界面卡片数 == 期望值" → 受异步链影响
**原因**：卡片有**两条异步链**（兜底 → 接口），先后到达并改变集合。
**改**：① 等**连续多轮稳定**再读；② 断言**语义性质**（"无越级卡片"）
而非硬编码数量；③ 与**接口返回值交叉验证**。

### 9. 点门户卡片当入口 → 不跳转
**现象**：用例超时。
**原因**：门户卡片是**展示卡**，点击无效。
**改**：显式 `goto` 目标路由（先从路由定义确认路径）。

### 10. 精确匹配 `aria-label` → 同一控件两种文案
**原因**：兜底链与接口链给的 label 不同。
**改**：按**关键词子串**匹配（两文案的公共子串）。

## 二、测试设施陷阱

### 11. 登录限流（429）导致偶发失败
**改**：登录态复用 + 429 退避重试；并把"限流"与"密码错"用不同异常类区分。

### 12. `storage_state()` 不含 sessionStorage → 复用态没 token
**改**：额外抓取/回填 sessionStorage。详见 `login-reuse.md`。

### 13. **SPA 里"页面能打开" ≠ "token 有效"** → 假通过
**现象**："单跑通过、连跑失败"，后段断言接口数据时炸 401。
**原因**：前端拿本地 token **直接渲染**，不先校验 → 死 token 也能"登录成功"。
**改**：有效性校验**必须包含"真发一次请求探 HTTP 200"**。

### 14. `conftest.py` 被多人同时改 → 互相踩
**现象**：`AttributeError: 'FixtureFunctionDefinition' object has no attribute ...`
（fixture 参数漏声明，闭包抓到了模块级的 fixture 对象）
**改**：**`conftest.py` 单点维护**，其他人只读；缺的工具写自己文件里。

### 15. 用例直接 `import` 业务模块 → 宿主机缺依赖
**现象**：`ModuleNotFoundError: No module named 'xxx'`（业务依赖只在容器里）。
**改**：**e2e 只走 HTTP + 浏览器**，不 import 业务代码。
若需验证"内部逻辑"，改用**接口层 + 运行期日志**，或用 `ast` 做**源码结构断言**
（比字符串 `in` 硬 —— 字符串匹配会被注释/docstring 满足）。

### 16. 临时探针脚本放 `tests/e2e/` → 污染目录
**改**：临时脚本放 `_scratch/`；且**删除**（含 `__pycache__` 残渣）。

### 17. Chromium 下载失败（下到 90% 断连）
**改**：用镜像
```bash
PLAYWRIGHT_DOWNLOAD_HOST=https://registry.npmmirror.com/-/binary/playwright \
  python -m playwright install chromium
```

### 18. 登录态缓存含真实 token 但未 gitignore → 凭据入库
**改**：`.gitignore` 加 `tests/e2e/artifacts/`。

## 三、假失败归因（**上报前必查**）

出现失败时，**先按这三类排查，不要直接当产品缺陷报**：

| 类别 | 特征 | 检查方法 |
|---|---|---|
| **产品缺陷** | 后端日志/接口确实异常 | 看日志、直连接口复现 |
| **测试自身问题** | 单跑通过、连跑失败；报错在测试代码行 | 单独跑该用例；看是否有 `TypeError`/`NameError` |
| **环境问题** | 依赖缺失、限流、服务不通 | 检查依赖、429、连通性 |

**实测中真实发生过的"测试自身问题"**：
- 漏声明 fixture 参数（→ `FixtureFunctionDefinition` 报错）
- 函数体被误清空只剩 docstring（→ 隐式返回 `None` → `TypeError: concatenate NoneType`）
- 重写函数时**留下旧定义**，Python 取后定义把新的遮蔽（→ `NameError`）
- 关键词取得太窄（→ 假失败）
- 用固定窗口判否定语境（→ 假失败）

**结论**：**报缺陷前先证明它是产品问题**。测试自身的 bug 要如实说明，
但**不要当成产品缺陷上报** —— 那会浪费对方的时间，也损害测试可信度。

## 四、耗时优化（不牺牲断言强度）

| 手段 | 说明 |
|---|---|
| **日志判据提前收尾** | 命中拒绝日志立即停止等待（实测 240s → 10~13s） |
| 登录态复用 | 省掉每次登录 |
| 分文件跑 | 便于定位，避免限流累积 |
| 长任务只验关键节点 | 面板出现/标题正确即可，不等完整产物 |

⚠️ **不要为了快而砍断言强度**。若慢的根因是**产品行为**（如越权要 3.5 分钟才给结论），
就如实接受 —— 缩短等待等于用时间换掉断言。

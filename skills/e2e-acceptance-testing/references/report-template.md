# 验收报告结构模板

> 目标读者是**组长 / 交付验收方**，不是开发者。
> 原则：**结论先行、证据可查、问题不藏**。

## 报告结构（8 节）

```markdown
# <系统名> 端到端功能验收测试报告

**测试日期**：YYYY-MM-DD
**测试环境**：前端 URL / 后端 URL
**测试方式**：Playwright（真实浏览器驱动）+ HTTP 接口级断言，双源交叉验证
**测试范围**：<功能域清单>

## 一、总体结论
| 项 | 数值 |
|---|---|
| 用例总数 | N 条（M 个测试文件） |
| 通过 / 失败 / 跳过 | |
| 已知缺陷哨兵（xfail） | |
| 总耗时 | |

**本轮共发现并修复 N 个真实缺陷**（详见第四节），另有 M 个已定位待决策。

> **测试方式说明**：这不是"看界面截图"的测试，而是脚本驱动真实浏览器执行完整
> 用户路径（真登录 → 真发消息 → 真等结果 → 真读结果），断言写在脚本里。
> 关键性质**同时用界面和后端接口两个来源交叉验证**，避免单一来源的假通过。

## 二、测试用例清单（按功能域）
### A. <功能域>（`test_xxx.py`，N 条）
| # | 用例 | 类型 | 验证点 |
（每个功能域一张表）

## 三、最终执行结果
### 3.0 界面截图证据
（**成功场景 + 失败/拒绝场景**，分组呈现；每张配一句"它证明什么"）
### 3.1 分文件结果
| 文件 | 用例数 | 通过 | 失败 | 跳过 | xfail | 耗时 |
### 3.2 结果明细
（xfail 逐条说明：缺陷是什么、现状如何、修好后会变 XPASS）
### 3.3 关键验证证据（摘录）
（**后端日志原文**、接口对照表 —— 客观证据）

## 四、发现并修复的真实缺陷
### 🔴 缺陷 A：<一句话现象>（安全 / 功能）
**现象**：<含日志/接口对照的铁证>
**根因**：<为什么>
**修复**：<怎么修的>
**验证**：<怎么证明修好了>
（每个缺陷都按这个结构）

## 五、已定位、待决策的缺陷
| 方案 | 做法 | 影响 |
（给出可选方案，让决策者选）

## 六、其他已知问题（低优先级）
| # | 问题 | 说明 |

## 七、测试资产
| 文件 | 用例数 | 功能域 |
**运行方式**：`python -m pytest tests/e2e -v`
**测试账号**：<角色 / 授权范围>

## 八、方法论说明（为什么这样测）
（回答"为什么需要 e2e" —— 用本轮实际发现的缺陷说明
 单测/接口测试覆盖不到什么）
```

## 写作要点

### ① 结论先行，数字说话

开头就给"用例数 / 通过率 / 发现问题数"，不要让人翻到最后才知道结果。

### ② 证据要"可查"，不要"我说"

❌ "越权请求被拒绝了"
✅ 贴**服务端日志原文**（含时间戳），必要时给**修复前后对照**：

```
<时间>  <模块> - 范围校验拒绝：<对象ID> 不在可见范围（可见：<允许值>）
<时间>  （修复前）<取数模块> : <对象ID> -> <N> 条数据        ← 缺陷证据
        （修复后）无任何越界取数记录                          ← 修复证据
```

**接口类问题用"对照组"呈现**（同请求头、不同端点）：

| 请求 | 结果 |
|---|---|
| A 端点 + 正确凭据 | 🔴 500 |
| B 端点 + **同一组凭据** | ✅ 200 ← 证明是 A 自身的问题 |

### ③ 截图要"证明什么"，不只"是什么"

| 截图 | 它证明什么 |
|---|---|
| 越权被拒 | 拒绝 + **任务清单「0/7 项」证明未生成** |

**失败/拒绝场景的截图最有价值** —— 它证明"系统在异常情况下的表现是对的"。

### ④ 问题分级，不藏

- 🔴 安全 / 🟠 功能 / 🟡 待决策 / ⚪ 低优先级
- **已修的和未修的分开写**，未修的给出可选方案
- **测试自身的 bug 也要说明**（避免被当成产品缺陷）

### ⑤ 如实标注"偏差"

实测中遇到的情况，**必须在报告里写清**：
- 整目录连跑时某条**偶发失败**（单独跑通过）→ 说明原因，并给出"本报告数字来自分文件独立运行"
- 某条**跳过**（如界面结构待确认）→ 标注"非产品缺陷"
- 某条 **xfail** → 说明缺陷与现状

### ⑥ 方法论那节很重要

**它回答"为什么要花这个成本"** —— 用本轮实际发现的缺陷说明：
哪些是单测发现不了的（模型行为选择、多入口不一致、完整鉴权链、端点间对比）。

## 生成 HTML（单文件 + 点击放大）

```bash
python md2html.py 报告.md 报告.html
```

产物特性：
- **图片 base64 内嵌** → 单文件可转发（邮件/IM 不会丢图）
- **点击图片放大**（灯箱：点图放大、点任意处/Esc 关闭、滚轮缩放、拖动平移）
- **零外部依赖**（纯 CSS + 原生 JS）→ 离线可用
- 打印时灯箱自动隐藏

⚠️ **不要给图片加 `loading="lazy"`** —— 部分邮件客户端/预览器不生效，
收件人会看到空白。报告是要转发的，**全量预加载更稳**。
